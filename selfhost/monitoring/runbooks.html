Chronicle monitoring runbooks

Run ./chronicle doctor first. After repair, both ./chronicle doctor and ./chronicle verify must pass.

Backend down

Confirm with ./chronicle status and ./chronicle logs backend. Correct the first fatal configuration, migration, disk, or dependency error; then run ./chronicle up.

Database down

Run ./chronicle logs postgres, correct the first fatal error, and run ./chronicle up. Never delete the PostgreSQL volume as a repair.

TDE unhealthy

Confirm with ./chronicle check and ./chronicle logs db-init postgres. An unavailable principal key, wrong default table access method, or unconverted table is the likely cause. Do not recreate the keyring. Follow the bundled TDE recovery guidance, run ./chronicle up, and verify this alert clears.

Web listener down

Run ./chronicle logs web, correct its certificate, port, or upstream error, and run ./chronicle up.

Participant endpoint unreachable

Probe $CHRONICLE_PUBLIC_BASE_URL/health from another machine, or https://$DOMAIN/health when the override is blank. Repair DNS, TLS, proxy, firewall, or listener binding; then run ./chronicle verify.

Logs unavailable

Run ./chronicle logs victorialogs fluent-bit. Correct the first storage, parsing, or connectivity error and restart those two services.

Configuration invalid

Run ./chronicle check, correct every FAIL line in .env, then run ./chronicle up.

Operational probe stale

Run ./chronicle logs operational-probe and restart that service after correcting its first error.

Backup stale

Backup invalid

Run ./chronicle logs db-backup and gzip -t backups/last/*.sql.gz. Correct database, backend, disk, or scheduler failure and restart db-backup.

Disk pressure

Inode pressure

Run df -h and df -i. Add disk first or remove only documented disposable artifacts; never remove Chronicle data volumes.

Deletion failures

Database rollbacks

Use Operational Logs at the alert time and correlate by error/request ID. Confirm with ./chronicle doctor and ./chronicle logs backend. Likely causes are invalid workflow state, database pressure, exhausted disk, or a backend defect. Correct the first reported cause, run ./chronicle up, and verify that the dashboard rate returns to zero.

Database connection pressure

Confirm with the Database and Storage dashboard and ./chronicle logs postgres backend. Long-running requests, stuck workers, or an undersized connection limit are likely causes. Correct the failing workload before changing limits, run ./chronicle up, and verify connection usage remains below 80%.

Repeated restarts

Container OOM

Inspect the named container and compare its dashboard memory to the configured limit. Change limits only after identifying the pressured service.

Certificate expiry

Inspect the served certificate with OpenSSL, renew or replace it at the terminating proxy/Caddy, then run ./chronicle verify.

Operator command failed

Correlate Operational Events with logs, rerun ./chronicle doctor, and follow the command-specific recovery text.

Disk predicted full

Confirm with ./chronicle doctor and df -h. Growth or an undersized disk is usually responsible. Increase disk capacity or lower the documented retention setting, restart the affected monitoring store, and verify its budget panel falls below 80%.
